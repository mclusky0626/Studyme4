# Studyme3 기준선과 위험 감사

조사 기준: `mclusky0626/Studyme3`의 `main` 브랜치, 커밋 `dd3219a`.

## 유지할 동작

- `bot.py`: DM, 호명어, 멘션, 봇 메시지 답장 감지
- `bot.py`: 채널별 최근 대화 버퍼, 대화 상대 추적, 메시지 디바운스
- `bot.py`: `[pass]`, 이모지 단독 응답을 반응으로 전환, Discord 2,000자 분할
- `llm.py`: 공급자별 OpenAI 호환 어댑터, 도구 실패가 대화를 죽이지 않는 처리
- `relations.py`: Discord ID를 정체성의 기준으로 사용하고 관계를 정형 데이터로 저장한 판단

## 확인된 위험

| 심각도 | 위치 | 위험 | v2 처리 |
|---|---|---|---|
| 매우 높음 | `bot.py:300`, `memory.py:30-43` | 자동 검색이 `memory.search(content)`를 사용자·서버 필터 없이 호출하여 다른 사람/서버/DM 기억이 섞일 수 있음 | 공개 범위 SQL 조건과 subject 필터를 저장소 계층에서 강제 |
| 매우 높음 | `tools.py:190-204` | 답변 LLM이 기억 저장과 물리 삭제를 직접 호출 | 응답과 추출 모델을 분리하고 검증기만 쓰기 허용 |
| 높음 | `bot.py:90-94` | 새 발언과 모순되면 과거 기억을 즉시 삭제하여 역사와 근거가 소실 | `superseded`/`disputed` 상태와 `MemoryRevision` 보존 |
| 높음 | `bot.py:723-730` | `!기억 @유저`로 타인의 기억을 누구나 조회 가능 | ephemeral 슬래시 명령으로 자기 기억만 조회 |
| 높음 | `relations.py` | 관계에 `guild_id`가 없어 서버 간 관계가 섞임 | 모든 관계와 관계 이벤트에 `guild_id`, 근거 메시지 저장 |
| 높음 | `bot.py:125-143` | 최근 대화·진행 상대가 프로세스 메모리에만 존재 | Message와 ChannelState를 PostgreSQL에 영속화 |
| 중간 | `bot.py:270-385` | 이미지를 로컬에 자동 저장하고 장기 기억에 자동 등록 | v2 MVP에서 이미지 저장 비활성화 |
| 중간 | `bot.py:707-721` | 일반 유저가 전역 페르소나를 변경 가능 | 배포 환경의 버전 관리 설정만 사용 |
| 중간 | `bots.json` 로딩 | 토큰을 평문 로컬 JSON에 둘 수 있음 | 배포 비밀 환경 변수만 사용, 파일은 Git 제외 |

## 기준선 결론

Studyme3의 대화 경험은 재사용 가치가 있지만 기존 데이터 계층 위에 서버 격리를 덧붙이는 방식은 안전하지 않습니다. v2는 Discord 어댑터의 UX 개념만 옮기고, 원문·기억·관계·상태의 저장과 권한 경계를 새 스키마로 교체합니다.
