# Studyme3 → v2 데이터 마이그레이션 계획

기존 ChromaDB 문서에는 `user_id`, `user_name`, `ts`가 있지만 `guild_id`, `channel_id`, DM 여부와 Discord 원문 메시지 ID가 없습니다. 기존 SQLite 관계에도 서버 ID가 없습니다. 이 누락값을 추측해서 공개 범위로 가져오지 않습니다.

## 절차

1. 기존 `data/` 디렉터리를 중지 시점 스냅샷으로 백업한다.
2. `scripts/audit_studyme3_data.py`로 읽기 전용 보고서를 만든다.
3. Chroma 기억은 v2의 `user_private` 격리 기억으로 가져온다. 대화에는 사용하지 않고 유저가 `/기억보기`로 검토한다.
4. 사용자가 승인한 기억만 실제 서버/채널 범위와 원문 근거를 지정해 활성화한다.
5. 관계는 운영자가 정확한 `guild_id` 매핑을 제공한 행만 이전한다. 매핑 없는 행은 보고서에 남기고 건너뛴다.
6. 샘플 환경에서 행 수, Discord ID, 중복, 공개 범위, 삭제 테스트를 검증한다.
7. 운영 DB 백업 후 짧은 쓰기 중지 구간에 최종 이전한다.

## 롤백

- v2 이전은 새 DB에만 쓰며 Studyme3 데이터를 수정하지 않는다.
- 실패하면 v2 DB를 폐기하고 백업한 Studyme3 데이터로 기존 봇을 재기동한다.
- v2가 안정될 때까지 Studyme3 백업을 읽기 전용으로 보관한다.

## 자동 이전하지 않는 항목

- 출처를 복구할 수 없는 기억의 `guild`/`channel` 승격
- 서버를 알 수 없는 관계
- 기존에 자동 저장된 이미지
- 삭제 이력이 없는 과거의 물리 삭제 정보
